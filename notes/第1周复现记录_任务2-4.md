## 8. 任务4 T2T 核对事项（代码已核对）
- 调用路径：model_name: two_stage → 评测器实例化 TwoStageInference（rosetta/baseline/multi_stage.py）；answer_method: generate → 调用 model.generate(...)
- 长度参数：unified_evaluator.py 第 1202–1203 行从 eval 读 communication_max_new_tokens / response_max_new_tokens，缺省均为 1024；论文写通信上限 256 → 在 yaml 中显式设为 256 / 64
- 输入格式：三轮对话
    user：background_prompt（嵌入不含选项的题干）
    assistant：Sharer 生成的背景
    user：完整题目（含选项和 Instructions）
  → Sharer 看不到选项；日志 Example IO 只打印最后一轮原题，看不到背景
- 重复推理：评测器在 generate 之后又调用 model.process()（第 1218–1225 行）专门用于记录，上限退回实例默认值 64（来自 generation_config）
    csv/日志中的背景是 64 token 截断版；实测 20/20 为真实背景的前缀
    cot_gen_length = 答案长度 + 64 截断背景长度，不能代表真实背景长度
    耗时约翻倍；为保持官方代码原样未修改
- apply_generation_config（rosetta/utils/evaluate.py 第 212 行）只 setattr model.generation_config，不包装 generate；调用时显式传入的 max_new_tokens 优先
- 真实背景长度（n=20，上限 1024）：中位数 57，平均 160，最大 790；超过 64 的 9/20，超过 256 的 4/20，达到 1024 的 0/20；超长的多为 "To determine/To answer..." 开头的分步推导
- 启动时的 attention mask 警告（pad = eos）：batch=1 时应无影响（未核对 batch 大小）

## 10. 与论文 §3 的对应
- 任务3 ↔ 公式 (1)：只用 Receiver 自己的 C(X) decode
- 任务4 ↔ §4.1 的 T2T 基线：Sharer 逐 token 生成文本，再拼进 Receiver 输入（序列变长）
- 任务2 ↔ 公式 (3)(4)：每层 C^F_n = C_n(X) + F_n(C_n(X), C^S_G(n)(X))，残差叠加，结果仍为 N 层、形状不变；decode 时只有输入部分用融合 cache，生成部分用 Receiver 自己的 cache
    N 个 F_n ↔ 28 个 C2CProjector；层映射 G ↔ projector_config.json；token 对齐 ↔ is_do_alignment / alignment_strategy "longest"（"最大字符串覆盖"）
- 效率：C2C 的 Sharer 只做一次 prefill，没有逐 token 生成，全量耗时约为 T2T 的 1/6
