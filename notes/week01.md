## 4. 观察与发现
- Qwen3-0.6B 有很强的 A 偏好（75% 的预测为 A；全答 A 的基线是 22.8%）
- overall_accuracy 是按题数统计的总体准确率，不是各学科准确率的平均（已用 csv 核对）
- receiver-only 模式下 rosetta_config 被忽略（日志中没有 projector 加载信息）
- 答案抽取：冒烟测试 275 题，与独立正则的结果 0 不一致
- 耗时估算：冒烟测试约有 75s 固定开销，全量耗时 ≈ 冒烟耗时 × 8

- T2T 相对 Receiver-only 提升 +5.56（论文 +5.50）；两个任务都比论文低约 0.5，可能是系统性小偏差（torch 版本 / GPU 数值）
- T2T 下 A 偏好从 75% 降到 63%
- T2T 实现（已核对代码）：三轮对话 user(background_prompt+题干，不含选项) → assistant(背景) → user(完整题目)；Sharer 看不到选项
- 评测器每题跑两遍两阶段：generate 用于判分（通信/作答上限读 eval 下的键，默认 1024），process 仅用于记录（上限 64）
- csv 中的背景是 64 token 截断版，20/20 是真实背景的前缀；cot_gen_length 不能代表真实背景长度
- 真实背景长度（n=20）：中位数 57，最大 790，超过 256 的 4/20，达到 1024 的 0/20
- two_stage 模式下 rosetta_config 被忽略

- fuser 加载已核对：evaluator 第1585行 → load_rosetta_model；28 个 C2CProjector，missing/unexpected=0，值逐元素一致，总参数 477.8M（论文 478M）
- load_rosetta_model 使用 strict=False 且 .pt 缺失时静默跳过 → 以后换 checkpoint 都要重做此检查
- C2C 不改变 Receiver 的文本输入，与任务3逐字相同
- C2C 下 104 条（1.8%）pred 为空，其中 81 条以"字母."开头（省略 "The correct answer is"）；若计入可多对 42 题（+0.75 → 43.99），正式分数不计
- C2C 下字母与选项内容不一致约 5%（冒烟测试），Receiver-only 为 0
- 选项偏好：R 偏 A(75%) → T2T 偏 A(63%) → C2C 偏 B(44%)
- 默认设置：multi_source_fusion_mode="sequential"，include_response=False
